Urban Mobility Analytics Engineering

A Databricks medallion pipeline built over official NYC taxi records, with PySpark and Delta Lake transformations, data-quality controls, dbt validation, rerun-safe processing, and Power BI operations reporting.

View GitHub RepositoryBack to Projects

Engineering problem

The project turns large official NYC taxi trip files into a repeatable analytical pipeline. The design emphasizes clear table grain, validation, idempotent processing, late-arriving-data handling, and a business-ready reporting layer rather than a one-off notebook.

Reliability controls

  • Schema enforcement prevents unexpected structure from silently entering the trusted layer.
  • Deduplication logic keeps repeated source records from inflating analytical totals.
  • Idempotent Delta MERGE behavior supports safe reruns instead of blindly appending duplicate data.
  • Late-arriving-data handling makes repeated ingestion more realistic and auditable.
  • dbt models and tests validate the analytical layer, with local checks automated through GitHub Actions.

Business intelligence layer

The final Power BI operations report summarizes the curated data in four pages. The repository documents the architecture, validation controls, and reproducible execution path so a technical reviewer can trace how a metric reaches the report.

What this project demonstrates: cloud data engineering, PySpark transformations, Delta Lake reliability patterns, analytical modeling with dbt, data-quality persistence, CI validation, and BI delivery over a multi-million-row dataset.

Design choices

The project uses a medallion architecture because the raw, validated, and aggregated layers have different responsibilities. Separating those layers makes the data lineage easier to review, allows bad records to be isolated before business aggregation, and gives the BI layer a stable Gold grain.
