Case Study · Product Analytics / Experimentation

Product Experimentation and Customer Analytics

A reproducible product-analytics case study covering event modeling, ordered funnel and cohort SQL, experiment integrity and inference, and time-aware retention modeling.

View GitHub RepositoryBack to Projects

Business problem

The project models a fictional subscription product that needs to understand funnel loss, compare acquisition segments, evaluate a signup treatment, and prioritize retention outreach. Treatment assignment and outcomes are synthetic and generated by the documented code, so the project demonstrates methodology rather than a real company experiment.

Data and analytical design

The full run contains 20,000 synthetic users and 129,937 events. The data model keeps event-level behavior separate from user-level treatment assignment and outcomes so funnel counts and experiment metrics are not inflated by repeated events.

GenerateSeeded synthetic users and events
ModelUser/event grain in DuckDB
AnalyzeFunnels, cohorts, segments
InferA/B test + SRM checks
PredictChronological retention model
ReportPower BI + decision outputs

Experiment analysis

The workflow evaluates treatment and control conversion with a two-proportion comparison, reports practical lift alongside statistical uncertainty, and checks assignment balance before interpreting the result.

Experiment metricResult
Absolute treatment lift+2.76 percentage points
95% confidence interval1.65 to 3.87 percentage points
p-value1.05e-6

Retention model

The retention classifier uses a chronological split and only features available before the prediction window. That design prevents future behavior from leaking into the feature set.

Model metricResult
ROC-AUC0.641
Average precision0.406

Validation and reporting

  • 20 of 20 persisted data-quality checks passed.
  • 11 automated tests passed in GitHub Actions.
  • Four Power BI pages were delivered for funnel, cohort, experiment, and retention analysis.
  • A separate BigQuery funnel was executed against Google's public GA4 sample; it is documented separately from the synthetic experiment so the two data sources are not conflated.
What this project demonstrates: product-metric design, grain-aware SQL, A/B testing, statistical inference, leakage control, predictive modeling, cloud SQL exposure, automated validation, and business-facing BI.

Limitations

  • Synthetic behavior cannot establish external validity for a real product.
  • The retention model is predictive; it does not establish that changing a feature will causally improve retention.
  • A real experiment would require production instrumentation QA, pre-registration, power planning, guardrail monitoring, and organizational review.
